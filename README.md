# Кортеж — SQL за 12. клас

Сайт, в който учениците четат уроците по SQL (по учебника на Манев и кол., Клет, Модул 3), пишат заявки, изпълняват ги и ги проверяват на място. Учителят вижда кой докъде е стигнал и какво точно е писал.

Всичко е **безплатно** в Cloudflare: Pages за сайта, Functions за проверката и D1 за акаунтите и напредъка.

---

## Какво има вътре

- **9 урока** (уроци 15–25 от учебника): SELECT, WHERE, ORDER BY / GROUP BY, параметризирани заявки, CREATE / INSERT / UPDATE / DELETE, ALTER и ограничения, JOIN, вложени заявки, обобщение.
- **104 задачи**: 85 SQL задачи и 19 тестови въпроса. Бонус задачите са със звездичка.
- **Две примерни бази** по учебника: *Училище* (Ученик, Учител, Предмети, Оценки, Успех) и *Фирма* (Детайли, Доставчици, Доставя, Изделия, Служители).
- **Пясъчник** за свободни заявки.

### Как се проверява
- **▶ Изпълни** пуска заявката в браузъра на ученика (SQLite) и показва резултата веднага.
- **✓ Провери** изпраща заявката на сървъра. Там тя се изпълнява върху чисто копие на базата и резултатът се сравнява с този от верното решение. Така се приема **всяко** вярно решение, не само едно конкретно написване.
- Верните решения **не стигат** до браузъра на ученика, а резултатът се записва от сървъра. Напредъкът не може да се „нагласи“ през F12.
- Проверката пуска заявката и върху **скрит втори вариант на данните**. Ако ученикът е написал конкретна стойност (напр. `WHERE Average < 4.82`) вместо да я пресметне, или условието е вярно само случайно, проверката не минава.
- Параметризираните задачи (`:номер`, `:клас`) се проверяват с няколко различни стойности.
- Ученикът получава подсказка какво не е наред: брой редове, брой колони, подредба, ред на колоните, грешка в SQL на български.

### Учителят вижда
- Таблица с всички ученици и колко задачи е решил всеки по всеки урок.
- По урок: матрица ученик × задача (✓ / ✗ / брой опити). Цъкаш и виждаш какво е написал всеки.
- По ученик: всички задачи с последния и с верния отговор и цялата история на опитите с дата и час.
- Последна активност: живият поток от предадени решения.
- Класове с кодове за регистрация (отваряш и затваряш регистрацията).
- Отваряне и заключване на уроци. Учениците виждат само отворените.
- Смяна на парола, спиране, преместване в друг клас и изтриване на ученик.

## Качване (еднократно, ~15 минути)

Нужни са ти безплатен акаунт в **Cloudflare** и **GitHub**.

### 1. Качи файловете в GitHub
1. В GitHub натисни **New repository**, име `kortezh` (може и Private), **Create repository**.
2. На страницата на празното хранилище натисни **uploading an existing file**.
3. Разархивирай `kortezh.zip` и провлачи **всичко от папката** (папките `public`, `functions`, `content`, `tools` и файловете) в прозореца. **Commit changes**.

### 2. Създай базата D1
1. В [Cloudflare](https://dash.cloudflare.com) отвори **Storage & Databases → D1 SQL Database → Create**.
2. Име: `kortezh`, **Create**. Таблиците не се правят на ръка, сайтът ги създава сам при първото отваряне.

### 3. Създай сайта (Pages)
1. **Workers & Pages → Create → Pages → Connect to Git**, избери хранилището `kortezh`.
2. Настройки за build:
   - Framework preset: **None**
   - Build command: *(празно)*
   - Build output directory: **`public`**
3. **Save and Deploy**. След минута има адрес от вида `https://kortezh.pages.dev`.

### 4. Свържи базата със сайта
1. В проекта на Pages: **Settings → Bindings → Add → D1 database**.
2. Variable name: **`DB`** (точно така, с главни букви), D1 database: **kortezh**, **Save**.
3. **Deployments** → при последното внедряване **⋯ → Retry deployment**. Връзката важи от следващото внедряване.

### 5. Първо влизане
1. Отвори адреса на сайта. Първия път той сам те пренасочва към **настройка на учителския профил**: име, потребителско име, парола (поне 8 знака).
2. В панела отвори **Класове**, създай клас (напр. `12а`) и ще получиш код (напр. `12A-K7QP`).
3. Дай на учениците адреса и кода. Те натискат **Регистрация**.
4. Когато всички са се регистрирали, **затвори регистрацията** за класа.
5. В **Уроци** заключи уроците, до които още не сте стигнали.

> Ако сайтът покаже „Базата D1 не е свързана“, стъпка 4 не е довършена или не е направен Retry deployment.

## Промени по съдържанието

Уроците и задачите са в `content/lessons.mjs`, а базите в `content/databases.mjs`. След промяна:

```bash
npm install
npm run build   # проверява ВСИЧКИ решения и генерира файловете за сайта
npm test        # пробва проверката с верни и грешни отговори
```

`npm run build` спира с грешка, ако решение не работи, ако подредбата в задача с ORDER BY не е еднозначна или ако параметрите не променят резултата. След това качи променените файлове в GitHub и Cloudflare сам ще обнови сайта.

Локално пускане: `npm run dev` → http://localhost:8788

## Структура

```
public/              сайтът (това вижда браузърът)
  index.html         вход / регистрация
  app.html, app.js   страницата на ученика
  teacher.html, .js  учителският панел
  setup.html         първоначална настройка
  content.js         уроците БЕЗ решенията (генериран)
  engine.js          SQL машина и сравнение на резултати (генериран)
functions/
  api/[[path]].js    сървърът: вход, проверка, учителски данни
  _lib/content.js    задачите С решенията (генериран, не стига до браузъра)
  _lib/sql-wasm.*    SQLite за сървъра
content/             изходните уроци, бази и SQL машина
tools/               build и тестове
```

## Бележки

- SQL-ът е стандартният (SQLite), не диалектът на MS Access: `%` и `_` в LIKE вместо `*` и `?`, `LIMIT` вместо `TOP`, текст в `'единични кавички'`. Разликите са отбелязани в уроците.
- При кирилица LIKE различава малки и главни букви: `'Б%'` намира „Бойка“, а `'б%'` не. Това е отбелязано в урок 2.
- Безплатният план на Cloudflare стига с много: 100 000 заявки на ден и 5 GB в D1. Една проверка отнема няколко милисекунди.
- Паролите се пазят хеширани (PBKDF2), никъде не стоят като текст.
